PRACTICE 3 / 学習ノート 実習3

正しい記述はどれか

⑴〜⑹ の記述が正しければ ○、誤っていれば ✕ をタップ。判定後に根拠が表示される。もう一度タップで戻せる。

⑴
HTML で Web ページを作成する場合、ページの最後 に文字コードやタイトルなどを指定する。
○✕
✕ 文字コードやタイトルは、ページの最後ではなく 前部にあるヘッダ部(head) で指定する。表示される本文は body に書く(→ 参考A)。
⑵
画像ファイルを用いる場合には、カメラで撮影した画像データをそのまま 用いるとよい。
○✕
✕ カメラで撮影した画像は一般にファイルサイズが大きいため、ネットワークへの負荷を軽減するよう、必要最小限のサイズに変換 してから用いる。
⑶
外部サイトにリンクをする場合、もとのページを残したまま別のタブで表示 する指定ができる。
○✕
○ リンクには別タブ・別ウィンドウで開く指定ができ、もとのページを残したまま外部サイトを表示できる。
⑷
画像を表示する場合、alt 属性 を用いて代替テキストを指定することにより、アクセシビリティを高めることができる。
○✕
○ 画像が表示されないときや読み上げ環境でも、alt の代替テキストが内容を伝える。アクセシビリティ(→ POINT 09・参考B)を高める。
⑸
リンクは、メニューの Web ページへ戻るため以外では設定してはいけない。
○✕
✕ 内容によっては サイト内の関連ページにリンクする網状構造が適する場合 がある(→ 実習1)。リンクをメニュー復帰だけに限る決まりはない。
⑹
公開されている地図提供サイトの中には、地図を自分の Web ページに埋め込む ことができるものがある。
○✕
○ 地図サービスなどは、所定のコードを貼り付けることで自分のページに地図を埋め込める(アクセス案内などで使われる)。

APPENDIX A / HTML の骨組み

HTML の基本構造

ページは head(ページ自体の情報) と body(表示される内容) に分かれる。実習3⑴で「文字コードやタイトルは前部のヘッダ部」と言うのは、この head のこと。

<!DOCTYPE html> <html lang="ja"> <head> ←ページ自体の情報(表示されない) <meta charset="UTF-8"> ←文字コード <title>学部紹介</title> ←タブに出る題名 <link rel="stylesheet" href="style.css"> ←CSS を読み込む </head> <body> ←ここに書いた内容が表示される <header>…ロゴ・サイト名…</header> <nav>…メニュー…</nav> <main>…主たる情報…</main> <footer>…著作権・問い合わせ…</footer> </body> </html>

タグ(⑦)は「〈」と「〉」で囲んだ目印で、ふつう <main> … </main> のように開始と終了で内容を挟む。header / nav / main / footer は実習2の 4 領域にそのまま対応する。

APPENDIX B / alt の良し悪し

alt は「画像の代わりに読む文章」

画像が表示できないとき、また目の不自由な人が読み上げ(スクリーンリーダー)で閲覧するとき、alt の文字がそのまま読まれる。何を書くかでアクセシビリティ(POINT 09)が大きく変わる。

弱い alt 中身が伝わらない
<img alt="画像">

「画像」「写真」やファイル名だけでは、見えない人に何の画像かが伝わらない。空のまま(alt="")にすると、読み上げで飛ばされてしまう。

▶
良い alt 内容を言葉で説明
<img alt="桜の咲く本学の正門">

画像が伝えたい内容を短い文で書く。読み上げ環境でも内容が分かり、検索エンジン(⑫ SEO)にも画像の内容を伝える手がかりになる。

※ ボタンや意味のない飾り画像など、読み上げる必要がない画像は、あえて alt="" にして読み飛ばさせるのが正しい場合もある。

APPENDIX C / 端末に合わせる仕組み

同じ HTML を、端末に合わせて見せ分ける

レスポンシブデザインは、HTML は 1 つのまま、画面の幅に応じて適用する CSS を切り替える。スライド8の実演で、画面幅を狭めるとメニューが縦に積み直されたのがこれにあたる。

幅で切り替える「メディアクエリ」

CSS の @media

CSS には「画面幅が◯◯ px 以下のときだけ、このスタイルを使う」という指定ができる。これを メディアクエリ といい、その境目の幅を ブレークポイント と呼ぶ。例: @media (max-width: 720px) { … } はスマホ向けの指定。

端末に幅を正しく伝える viewport

head の meta

スマホで正しく表示するには、head に <meta name="viewport" …> を書いて「画面の実際の幅で表示してほしい」と伝える。これがないと、スマホが PC 幅のページを縮小表示してしまい、文字が小さく読みにくくなる。

同じ URL・同じ HTML で PC でもスマホでも読みやすく見せられるため、管理が 1 つで済み、検索評価(SEO)の面でも有利とされる。
