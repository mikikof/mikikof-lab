FIGURE · 連続 と 離散

なめらかな波を、階段に置きかえる

同じ「音の大きさ」でも、アナログはなめらかな波(連続量)。デジタルはとびとびの段階(離散量)で表す。音や画像のようにアナログ量をデジタルに直すときは、一定間隔で測って段階に置きかえるため細部がわずかに失われるが、数として正確に扱える。

①アナログ= なめらかな波。途中のどんな値もとり得る(連続)
②デジタル= 一定間隔で測った棒。段階の間の値はとれない(離散)

何ビットあれば足りるか

空欄①〜⑪をタップで正解を表示。「2ⁿ ≥ 表したい段階数」となる最小の n を探すのがコツ。前のスライドのスライダーで確かめながら。

3 桁の 2 進数は 000、001、010、011、（①）、101、110、111 の（②）通りであり、3 ビットで表現できる情報の数は（②)通り。これは 2 の（③）乗で求められる。
6 ビットで表現できる情報の数は（④）通り。1B と 2B を比べると、1B は（⑤）ビットだから（⑥）通り、2B は（⑦）ビットだから（⑧）通りとなり、2 倍ではなく（⑨）倍になる。

⑪ の考え方:0.0℃から 50.0℃を 0.1℃刻みで測ると 501 段階(0.0, 0.1, …, 50.0)。2⁸ = 256 では足りず、2⁹ = 512 ≥ 501 なので 9 ビット。

APPENDIX A / 0 と 1 を選んだ理由

なぜ 10 進法でなく 2 進法なのか

人は指が 10 本だから 10 進法を使う。ではコンピュータはなぜ 2 進法か。鍵は「電気で動く機械にとって、何段階なら間違えにくいか」にある。

2 値(0 と 1)
高い・低いの差が大きいので、多少乱れても読み違えない。スイッチ 1 つで確実に作れる。
vs
10 値(0〜9)
段の幅が狭く、わずかなノイズで隣の値に化ける。区別する回路も複雑になる。
WHY 2 IS ENOUGH

2 状態は「そのまま」作れる

電圧の 高い / 低い、電流の 流れる / 流れない ― この 2 状態をスイッチ 1 つで作り、0 と 1 に対応させれば、数も文字も画像もすべて表せる。

SPEED · COST · ACCURACY

差が大きいほど間違えにくい

2 値は高低の差が大きく、ノイズに強い。多値より 速く・安く・正確に作れる。だから 2 進法が世界標準になった。

つまり 2 進法は「桁が増える」短所より、確実さ・作りやすさ の長所が大きい。桁が増えて読みにくい分は、16 進法(⑤⑥)で補う。

APPENDIX B / 単位の階段

ビットから、KB・MB・GB の階段へ

情報量は 8 ビット = 1 バイト から始まり、バイトより上の単位は慣例的に 1024 倍 ごとに名前が変わっていく。スマホの容量「64GB」も、写真 1 枚の「3MB」も、すべてこの階段の上にある。

最小の bit から、×8 で B、その上は ×1024 ずつ 名前が変わって積み上がる
bit → B → KB → MB → GB → TB

8 ビット = 1 バイトから始まる

8 ビット = 1 バイト(B)。容量はここを最小単位に積み上がる。1KB≒千B、1MB≒百万B、1GB≒十億B、1TB≒一兆B。スマホの「64GB」も写真の「3MB」もこの階段の上。

2¹⁰ = 1024

なぜ 1000 でなく 1024?

コンピュータは 2 進数が基本なので、区切りも 2 の累乗が自然。2¹⁰ = 1024 がちょうど 1000 に近いので、これを 1 段の倍率に使う(実習4 の「1024 倍ごと」)。

APPENDIX C / 先頭ビット = 符号

先頭のビットで、正か負かを見分ける

固定長のビット列では、いちばん左(先頭＝最上位)のビットを「符号」の目印に使う。先頭が 0 なら 0 以上、1 なら負と読み分ける。ただし「残りのビット = 大きさ」とは限らず、表し方によって読み方が違う(下のカードを参照)。

先頭ビットで 0 以上か負か が分かる。2 の補数では 先頭ビットの重み = −2n−1
素朴な方法

符号付き絶対値の弱点

「先頭=符号、残り=大きさ」とする素朴な方法もあるが、+0 と −0 の 2 つができたり、計算のたびに符号を場合分けする必要があり面倒。

2 の補数

補数なら自然に符号になる

2 の補数では、先頭ビットがそのまま符号になり 0 は 1 つだけ。読み方は 先頭ビットの重み −2n−1(例: 1101 = −8+4+0+1 = −3)。足し算の回路がそのまま使える。4 ビットなら −8〜+7 を表せる。

APPENDIX D / 補数 = 一周して 0 になる相手

「足すと 0 に戻る相手」を負の数にする

桁数を決めると、数は時計のように 一周して 0 に戻る。ある数 A に「足すとちょうど一周して 0 になる相手」を、−A の代わりに使う ― これが 補数 の考え方。

桁が決まると「輪」になる
→
足すと一周する相手 = 負
時計と同じ

一周して 0 に戻る

4 ビットは 0〜15 で、1111 の次はあふれて 0000。12 時の次に 1 時へ戻る時計と同じで、決めた桁の中で数は輪になる。

−A = 2ⁿ − A

足すと一周する相手を負に

A に足すと 2ⁿ(=一周=0) になる相手 2ⁿ − A を、−A とみなす。次ページの「反転して 1 を足す」は、この相手を作る手順。

APPENDIX E / 補数の作り方

反転して 1 を足す ― 補数の作り方

負の数(補数)の作り方はとても簡単で、全ビットを反転して 1 を足すだけ。これで引き算まで足し算の回路でこなせる。前ページの「一周して 0 になる相手」を、実際に作る手順がこれ。

反転して 1 を足すと、「足すと一周して 0 になる相手」= 負の数ができる
2 の補数

反転 +1 で −A を作る

全ビットを反転して 1 を足すと、足すと一周して 0 に戻る相手(= 負の数)になる。例:3=0011 → 1100 → +1 → 1101 = −3。なぜ一周で 0 かは下の補足(時計)で。

5 − 3 = 5 + (−3)

引き算が足し算になる

負の数を補数で表すと、引き算を 足し算の回路だけ で計算できる。5 − 3 → 0101 + 1101 = (1)0010 = 2(あふれた最上位は捨てる)。引き算専用の回路が要らない。

APPENDIX F / 実数のデジタル化

小数(実数)を 2 進数で表す

整数だけでなく、小数も 2 進数で表せる。小数点以下の桁の重みは 1/2・1/4・1/8… と 2 で割られていく。大きさの幅が広い実数は、符号部・指数部・仮数部に分ける 浮動小数点数 で表すことが多い。

小数点以下は 1/2・1/4・1/8… の重み。実数は 符号部・指数部・仮数部に分けて表す
0.101₂ = 0.625

小数点以下は 1/2・1/4・1/8…

整数部と同じく桁の重みを足すが、小数点の右では重みが 2 で割られていく。0.101₂ = 1/2 + 0 + 1/8 = 0.625。

FLOATING POINT

実数 = 符号部・指数部・仮数部

とても大きい数も小さい数も表せるよう、実数は 符号(S)・指数(E)・仮数(M) に分ける(浮動小数点数)。ただし、表しきれない小数では誤差が出る。
