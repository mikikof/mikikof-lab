# 情報Ⅰ 2学期 — 授業運用ハブ

50分の授業1回を、5つのキットにまたがって一式そろえる場所。
**このフォルダ配下のファイルに触れたターンから、以下の規則がそのセッションの残り全部に効く。**

---

## 1. なぜこの形にしたか

1学期は lectures（学習ノート）と practices（問題集）を授業内で使った。
アンケートで「授業内で使うのはあまり良くない」という結果が出た。

そこで役割を分けた。

| | 使う場面 | 何を担う |
|---|---|---|
| **解説ツール**（edu-explainer） | 授業内 25分 | 手持ちスライドと併用して、難所を動かして見せる |
| **印刷プリント**（印刷教材） | 授業内 15分 | 紙で解かせて、その場で解説する |
| **スピードテスト**（スピードクイズ） | 授業内 10分 | 速さ×正答率で復習する |
| **lectures** | 授業外 | 個人学習用。授業内では使わない |
| **practices** | 授業外 | 個人学習用。授業内では使わない |

lectures と practices は**質を落とさず作り続ける**。使う場面が変わっただけで、格が下がったわけではない。

---

## 2. 一回一難所（設計の芯）

**1回で扱う難所は1つに絞る。** 50分に3つの教材を詰めるのだから、3つが別々の話をすると何も残らない。

授業内の3点は、**同じ難所を三度通る**ように作る。

```
難所を1つ決める
  ↓
① 解説ツール  … 見せる      操作すると境界が動き、条件を満たす／満たさないが切り替わる
② 印刷プリント … 書かせる    手で計算・記述して、その難所を通る
③ スピードテスト … 速く判断させる  誤答の選択肢が、その難所の取り違えになっている
```

**難所を先に決めてから教材を作る。** 教材を作ってから難所を後付けしない。
難所は「初見で落ちる場所」であって、「内容として重要な場所」とは限らない。
学習ノートの POINT を上から順に均等に扱うのは、この設計ではない。

難所の選び方は `_ops/nansho-guide.md`。

---

## 3. アンカー

回は必ず**アンカー**を1つ持つ。学習ノートの POINT（= lectures の lec 番号）か、
ベストフィットの節（= practices の番号）。対応表は `_ops/manifest.yaml`。

- **アンカー教材が未作成なら、同じ回のフローの中で作る**（個人学習用の正本になる）
- **既にあれば公開 URL を案内するだけ**でよい（作り直さない）

50分のテーマは、アンカーより**狭い**。POINT 1つがそのまま1回になるとは限らない。
`_ops/manifest.yaml` の `anchor` と `theme` を別欄にしてあるのはそのため。

---

## 4. 公開安全（このフォルダ固有・最重要）

**`mikikof-lab` は public リポジトリ。ここに置いた物は GitHub 上で誰でも読める。**
GitHub Pages が配信するかどうかとは別の話で、リポジトリを開けば中身は見える。

### 追跡してよい

- 回のランディング `index.html`
- 回の設計と進行台本 `_ops/kai/NN-<slug>.md`（**解答を書かない・原本を書き写さない**）
- 解説ツールの HTML（自作。既に `joho-explainer` で公開している）
- 公開 URL のリンク集（`03_速テスト/README.md` / `04_個人学習/README.md`）

### 追跡してはいけない

- **解答**（プリント解答 HTML・PDF）
- **原本由来のもの**（教科書・学習ノート・ベストフィット・winstep の問題文全文、そこから抽出した画像）
- 生成器のコピー、配布 ZIP、配布リンク（クラス別 `?g=` 付き）、集計シートの URL

これらは `_teacher/` と `02_プリント/` に入れ、`.gitignore` で外す。**手元には残る**ので、
授業当日に回フォルダを開けば一式そろっている状態は変わらない。

### 消えても困らない形にしておく

回フォルダは**派生物**。実体の正本は my-company（private）側の各キットにある。
`python3 _ops/build_kai.py <回番号>` で組み直せる。手でコピーして育てない。

### 出荷ゲート

```bash
python3 _ops/check_public.py
```

**追跡 NG が1件でもあれば push しない。** このスクリプトはリポジトリ全体の版元著作物も報告する。

## 6. 工程

起動は **`/joho-2gakki`**。詳細は同スキルの `pipeline.md`。骨子だけ書く。

| Phase | やること | 抜けると起きること |
|---|---|---|
| 0 Intake | テーマ指示を受ける → アンカーを決める → **難所を1つ確定** → `_ops/kai/NN-<slug>.md` を起こす | 3点がばらばらの話をする |
| 1 検算 | 難所の数理を独立に検算する。原本（`source/`・解答PDF・ベストフィット解答）で正解を裏取りする。**web 検索しない** | 誤答を全教材に量産する |
| 2 授業用3点 | 解説ツール → 印刷プリント → スピードテスト。各キットの規則どおりに作る | 品質が毎回ぶれる |
| 3 アンカー教材 | 未作成なら lectures / practices を作る。既にあれば飛ばす | 個人学習の受け皿が欠ける |
| 4 整合 | §7 の整合ゲートを通す | 同じ例の数値が教材ごとに違う |
| 5 集約 | `build_kai.py <回番号>` で回フォルダを組む → 進行台本を仕上げる | 当日ファイルを探す |
| 6 配信 | 解説ツール → `~/joho-explainer`／スピードテスト → `~/joho-quiz`。それぞれの同期手順で | 生徒が開けない |
| 7 監査 | `/audit-review`（**web 禁止・教科書準拠**）。5件以上直したら再 audit。最後に `check_public.py` | 事実誤認と公開事故 |

---

## 7. 整合ゲート（この回の3点が一つの難所を指しているか）

Phase 4 で1項目ずつ通す。1つでも外れたら回フォルダを組まない。

- [ ] 難所が3点すべてに現れている（解説で見せ、プリントで書かせ、テストで判断させている）
- [ ] **同じ例の数値・記号・用語が3点で一致している**（標本化周波数、ビット数、変数名、単位の書き方）
- [ ] プリントの空欄が、その難所を通らないと埋まらない
- [ ] スピードテストの誤答選択肢が、その難所の**取り違え**になっている（無関係なダミーではない）
- [ ] 解説ツールの状態判定が、難所の境界そのものを表している
- [ ] 25分／15分／10分に収まる分量になっている（詰め込んでいない）
- [ ] 語尾がキットごとに正しい（丁寧体／常体／常体指示）。混ざっていない

---

## 8. 出荷ゲート

- 各キットの `quality-checklist.md` を通す（キットごとに違う。省略しない）
- 数理は**独立に検算済み**。正解は原本で裏取り済み。web 検索を使っていない
- 実機目視（解説ツール = headless Chrome で既定＋負の状態／プリント = グレースケール／テスト = `index.html?s=N`）
- §7 の整合ゲート 全項目
- `/audit-review` を通し、必須指摘を適用済み
- **`python3 _ops/check_public.py` が exit 0**
- `_ops/manifest.yaml` の当該回が `status: done` になっている

---

## 9. 文章

- ルート `../CLAUDE.md`「文章トーン」がそのまま効く（理路整然・抑制的・アカデミック）
- メディア部の AI 臭バンリスト（`../../../../media/CLAUDE.md` 軸1）が3キットに効く
- 進行台本も同じ規律で書く。自分に向けた台本でも、読み上げると生徒に届く
- 「やってみよう」「頑張ろう」「しっかり」「ぜひ」「重要なポイント」は書かない

---

## 10. モード

このフォルダは `mikikof-lab`（教育）と `media/webツール/情報`（メディア）の両方にまたがる。
**両方のモードが重ねて効く。**

- 最新最強の Opus を [1M] で使う。**世代を版で固定しない。** `/fast` 降格や Sonnet / Haiku を
  検出したら、続行する前に警告して止める
- 毎ターン ultrathink。1文の校正でも1つの図の設計でも省略しない
- 時間より品質を優先する。「ひとまずの案」を出さない
- `/audit-review` は教材 audit の作法（**web 検索禁止・教科書準拠**）。slug に `joho2-` を付ける
