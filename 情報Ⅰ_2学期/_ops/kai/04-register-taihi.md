# 第4回 同じレジスタに読み込めば、途中結果は消える

## 難所（1つだけ）

> 計算の途中結果がレジスタに入っていることを見落とし、次の値を同じレジスタへ READ してしまう。
> 読み込んだ瞬間に、途中結果は上書きされて消える。レジスタが 1 つなら先に主記憶へ書き出し、
> 2 つなら空いているほうへ読む。この一手が抜けると、命令の意味は全部言えるのに答えが合わない。

**型**: B 順序を入れ替えると壊れる

### なぜここが難所だと言えるか（原本の重み）

- 学習ノート 17 の実習4 は、解答 PDF（p.11）で**この POINT のなかで解説が最も長い**。
  途中結果をいったん主記憶に格納する必要がある、という理由まで書いてある。
  実習1〜3 の解説はラベルだけで、長さが際立って違う。
- 章末5（問題 p.45・解答 p.13）は同じ難所の裏返し。レジスタが 2 つあるので、解説は
  「すでに加算結果がレジスタ A に入っている」から次の値はもう一方へ読む、と書く。
  実習4 も章末5 も、見ているのは**値がいまどこにあるか**の一点だけ。
- ベストフィット 練習91⑸ は、加算命令の書き方を変えると結果が別のレジスタに残るので、
  書き出す命令のほうを直させる。ここも同じ一点。
- 命令の意味（READ・WRITE・ADD・SUB）を覚えても、並べる順で答えが変わる。
  飛ばして先へ進めない（`../nansho-guide.md` §1 の判定）。

## 3点への落とし方

| | 何をするか |
|---|---|
| ① 解説ツール（A 状態判定バナー型） | 仮想コンピュータを 1 命令ずつ実行する。プログラムカウンタ → 命令レジスタ → 命令解読器 → 演算装置と、取り出し・解読・実行の 3 拍で光る場所が動き、主記憶とレジスタの値が同時に変わる。命令の並びを「原本の並び」「退避を抜いた並び」「式を展開した並び」で切り替える。退避を抜くと、次の値を読んだ瞬間に途中結果が消えるところが見え、終了時にバナーが warn へ変わる |
| ② プリント（A 穴埋め記述型・常体） | 例題は実習4。記入表（命令ごとの、実行後のレジスタと 13 番地）を埋めながら 1〜5 番地の命令を選ぶ。退避の行を書かないと表が埋まらない。大問1 は CPU の中の装置、問一はレジスタ 2 つの章末5、問二は「退避を抜くとどうなるか」の記述 |
| ③ スピードテスト | 誤答に「退避を抜いた並び」「引く相手の番地の取り違え」「加算の結果が入るレジスタの取り違え」を置く。どれもこの回の取り違えそのもの |

### 空の番地を引いたときの言い方（3 点で揃えた）

退避を抜いた並びでは、減算のときに 13 番地がまだ空である。ここを**内部では 0 として計算する**が、
**画面には「引く相手がありません」と書く**。プリントの生成器が同じ語を使い、機械の assert で
結果を固定している。速テストはこの値に依存せず、失われるものだけを問うている。
**0 を引く、という明文化されていない約束を教えない。**

数理は spec を見ずに仮想機械を書いて独立に検算し、4 通りとも原本の解答と一致することを確かめた。
その過程で、spec の表が「空を 0 として扱う」前提の上に立っていることが分かり、
プリントと速テストの現物を開いて言い方を突き合わせた。

### 実物でしか出なかった欠陥（機械が緑のまま通っていた形・5 件）

1. **場面①で「レジスタ A」のラベルが 3 拍の箱の下辺に食い込んでいた。** 箱のあと 20px しか
   送っていなかった。はみ出しではないので図の検査は鳴らない。
2. **390px で番地のラベルが隣どうし接し、「10 番地（X）11 番地（Y）…」と 1 つの塊に見えた。**
   箱が 70px しかないのにラベルが約 95px あった。**はみ出しではなく接触**なので、これも鳴らない。
3. **箱の上のラベルを折り返すと、2 行目が箱の上辺に重なった。** 器に入らないときは
   短い言い方へ落とし、**折らせない**形に変えた。
4. **枡の下の役目が「途中結」「果」と折れ、1 文字だけが下へ落ちた。** 1 行で入らない幅では
   図から落とす（役目の詳しい言い方は本文の表が持っている）。
5. 図の文字の級数を `F(10.5 + 0.5)` と書いていた。実行時は 11px だが、**検査は静的に 10.5 と読む**。
